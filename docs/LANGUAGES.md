# Interface languages

Use **TR / EN** in the top-right corner to switch between Turkish and English.
Turkish is the initial default. The browser remembers the choice using
`sf-atlas-language` in local storage. When storage is unavailable, switching
still works for the current page.

The switch covers the catalogue, live controls, maps/world view, grail journal
and special/scenario-item guide. Search placeholders, tooltips, accessible
labels, item property names, scenario acquisition steps and later status/error
messages are included. English uses English number/percentage presentation;
grail dates follow the chosen locale.

Switching languages does not send a game command, reload a map, reset filters,
clear a draft trainer value or change an enabled feature. Element identities,
form values, event handlers and selection IDs are preserved. The game remains
in its installed language. Proper item/NPC names and imported CT scripts,
structure XML and source-code blocks are retained.

## Implementation

- `app/translations.js` is the checked-in TR/EN source-text catalogue. It is
  shipped with the app; no translation service or additional setup dependency
  is required.
- `app/i18n.js` records original text nodes and display attributes, translates
  them for English and restores those originals for Turkish. A mutation
  observer handles content generated by other modules and later API messages.
  It edits text/attributes, never reparses translated HTML or replaces controls.
- Template entries such as `{0} kayıt` support dynamic values. Placeholder
  boundaries avoid matching part of a longer word. Fixed labels also have
  uppercase variants for catalogue cards.
- Input values, code/script blocks and elements marked `data-i18n-ignore`
  are excluded from text translation. Placeholders and accessible labels are
  still localized on form controls.
- `atlas:languagechange` supplies the chosen language/locale. Grail dates are
  refreshed and the map canvas redraws labels without resetting its viewport.
- Backend state and command payloads retain their existing IDs and format;
  Turkish backend messages are translated at the display boundary.

Add new user-facing phrases and dynamic templates to `translations.js` when
adding features. Keep filenames, game identifiers and user-provided content
out of translation keys. Run `node tests/test_i18n.cjs` with the existing
development `jsdom` dependency to verify switching, persistence, dynamic
content, acquisition guides and the absence of game commands.
