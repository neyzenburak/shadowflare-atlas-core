# Native custom-resolution startup

Control Desk -> **Launch ShadowFlare** accepts width, height and the game
folder. The default is 1920x900. Settings apply on the next start; an existing
game is never closed or restarted by the launch button.

```powershell
.\start.cmd -LaunchGame -Width 1920 -Height 900
```

The implementation is authored against the verified original game's native
screen allocations, scene clipping, projection and HUD drawing/input paths.
It does not ship or invoke third-party configurator/patcher executables,
reproduce their configuration format, redirect their resources or include
their machine-code helper. Earlier helper-derived startup code was removed.
This describes the engineering provenance, not a clean-room legal claim.

`resolution_native.py` builds 29 scalar operand changes and four native code
changes from `viewport-plan.json`. The plan contains original-game instruction
fingerprints and operand metadata. Patch bodies are generated by Atlas.
The process starts suspended; all original spans are checked before code is
written, and every write is read back before the first thread resumes.

Two new scene hooks keep the full client clip rectangle and center the camera
on the character. Opening inventory/status overlays does not shift the camera.
The original HUD is rendered with `dx=width//2-320` and `dy=height-480`.
Matching clipping rectangles and HUD-local mouse input use the same transform.
World packets retain world coordinates. Existing inventory alignment, potion
right-click, tooltip and full-screen rain corrections remain integrated.

No HUD/NJP, EXE, DLL, save or game configuration file is rewritten. The old
`AtlasHUD`, `ResFix` and loader configuration files are not required or read.
The original menu artwork remains at its native size; the game scene uses
the chosen viewport. Supported geometry is 640x480 through 7680x4320, subject
to the machine's actual desktop and graphics-driver capabilities.

Protocol 19, launcher version 2 and display version 8 identify this path.
The HUD transform is enabled only when the running game has Atlas's native
viewport marker; a game started with another launcher keeps the earlier
compatible UI-correction behavior.

Verification includes original-game byte/instruction checks at multiple
resolutions, x86 scene/clip/camera tests, shared pixel/clip/mouse transforms,
existing-game protection, and a separate 1920x900 game copy with a loaded
character, centered HUD, full scene and right-aligned inventory.
